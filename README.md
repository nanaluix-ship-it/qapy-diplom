# qapy-diplom — Автоматизированное тестирование сервиса покупки туров

Дипломный проект по автоматизации тестирования веб-сервиса «Путешествие дня» (aqa-shop).

**Статус:** финальная версия, 47 автотестов, 5 подтверждённых дефектов (issues #1–#5).

---

## Что тестируем

Сервис покупки туров с двумя сценариями оплаты:

- Обычная оплата по дебетовой карте (Payment Gate)
- Покупка в кредит (Credit Gate)

Приложение передаёт данные карт банковским сервисам и сохраняет в БД только результат операции (статус, сумма, связи). Данные карт не сохраняются — проверено отдельными тестами.

**Стек:** Java (aqa-shop.jar), MySQL, gate-simulator (Node.js), Python (тесты), pytest, Selenium, allure-pytest.

---

## Как запустить проект

### 1. Поднять окружение (Docker Compose)

В корне проекта:

```powershell
docker compose up -d
```

Поднимутся:

- `mysql` — СУБД (порт 3306)
- `gate-simulator` — эмулятор банковских сервисов (порт 9999)
- `aqa-shop` — приложение (порт 8080)

Проверить, что всё поднялось:

```powershell
docker ps
```

Должны быть запущены все три контейнера.

### 2. Установить зависимости и активировать виртуальное окружение

```powershell
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Запустить автотесты

```powershell
pytest --alluredir=allure-results
```

Ожидаемый результат:

- Собрано 47 тестов
- 33 passed, 10 failed (целевые репродукции дефектов), 3 xfailed, 1 skipped

> ⚠️ Важно: 10 упавших тестов — это не случайные ошибки, а подтверждённые дефекты (issues #1–#5). Каждый тест завершается сообщением «БАГ ПОДТВЕРЖДЁН (issue #N)».

### 4. Сформировать и открыть Allure-отчёт

```powershell
allure generate allure-results -o allure-report --clean
allure open allure-report
```

В отчёте — детальные шаги, скриншоты, SQL-доказательства и ссылки на issues.

Подробные репродукции, ожидаемое и фактическое поведение — в issues репозитория и во вкладке Attachments Allure-отчёта.

## Требования к окружению

- Docker / Docker Compose
- Java и Node.js — уже включены в контейнеры
- Python 3.10+
- Зависимости из `requirements.txt`
- Установленный Allure Commandline (для генерации отчёта)

## Примечания

- Если тесты падают сразу после запуска — дайте 60–90 секунд на прогрев СУБД и приложения.
- Эмулятор шлюза может изредка давать вариативные таймауты ответов: возможны редкие флаки по таймаутам, не связанные с дефектами приложения (зафиксированы в Summary.md).
